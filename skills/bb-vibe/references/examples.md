# Examples

These use a new mobile game named Stacker: tap to drop a sliding block on the tower, the overhang is cut off, and a full miss ends the run. Nothing is built yet; there is a pastel mockup. The bad round comes from a real run. The good turns were written to show the shape.

## Bad: a questionnaire instead of a conversation

The first message gave one line on the project, then eight numbered questions at once, each with a recommended answer: the reference game ("Should Stacker feel like Stack?"), the view, the orientation, perfect drops, how the block moves, the run length in seconds and blocks, the look, and the music.

The user said: "Not a fan."

What went wrong:

- Eight things in one turn, so the user can only skim and say yes.
- Every question carried the agent's answer, so the agent set the character of the game and the user approved it.
- Some were the agent's own decisions. The mockup already settled the look, so the agent should have made it and reported it at a check-in.
- The run length came as numbers before the user had said what a run should feel like.

Fix: confirm the reading, then take one open point and ask it open.

## Good: opening

After reading the pitch and the mockup quietly:

> Nothing's built for Stacker yet, so I'm going from the rule (tap to drop, the overhang gets cut off, a full miss ends it) and your pastel mockup. Is that the game you have in mind, or has it moved on since?

User: "That's it."

## Bad: a feeling in the abstract

> Picture someone on the bus playing it. When they tap and the block lands on the tower, what should that moment feel like to them?

The user said: "I'm not sure how to answer questions like these. It should feel like the block landed?"

Fix: ask about what the player sees and hears, anchored to games that do it differently.

## Good: the first open point, asked concretely

> When a block lands in Stack, there's a soft click, the overhang drops off clean, and nothing moves. In Tower Bloxx, the block thuds down and the whole tower wobbles. In Suika Game, fruit lands with a squishy bounce. Or something new: each block lands with a note, and the notes of a run build into a tune. What do you want to see and hear when a block lands in Stacker: one of those, or something else?

## Bad: only copies

Every option named an existing game, so each choice was a pick between games, and the design differed from them only where the user brought an idea.

The user said: "This kind of guides us to copying everything. I don't mind the skill bringing up existing games, but I'd like some original ideas too."

Fix: put at least one original idea beside the references in every question.

User: "Stack, but I want it to feel a bit heavier when it lands."

> I like that. Stack can feel weightless, and a heavy landing gives the tap more punch. The risk is that a big landing slows the rhythm when you're stacking fast. What if the block lands with a short thud and a tiny squash, over in about a tenth of a second, so it feels heavy without slowing you down?

## Good: check-in

> Where we are. Still open:
> - What happens when you land a drop almost perfectly.
> - How fast it gets harder.
>
> Decided without asking since last time:
> - Portrait, and a tap anywhere drops the block, since it's a one-thumb phone game.
> - The look matches your mockup, with the tower stepping straight up, since the cut rule means nothing can lean.
>
> Where do you want to go next?
