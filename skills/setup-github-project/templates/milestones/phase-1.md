**What this phase represents:** A Prototype proves that the core idea works and is fun. It answers the largest technical and design risks with the smallest amount of work. Quality of art, audio, and code is not a goal. The team can replace most Prototype work in a subsequent phase.

**Work that belongs here**
- The core loop from start to end with placeholder assets.
- Proof of the risky technology, such as physics behavior, save data, input devices, and frame rate on the target devices.
- Simple versions of a system that show that the idea works.

**Work that does not belong here**
- Final art, final audio, and final UI style.
- Menus and settings that the core loop does not need.
- Code structure work, shared test tooling, and release automation.
- Long-term progression, more content, and store releases.

**Exit condition:** The team has evidence that the core loop works on the target devices and is worth more investment.
