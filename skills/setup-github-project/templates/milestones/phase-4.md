**What this phase represents:** Beta makes the game stable. The game is feature complete at the start and content complete at the end. The team corrects defects, tunes the game, and polishes it. The risk of each change must be low.

**Work that belongs here**
- Final versions of all remaining content and the replacement of each placeholder asset.
- Defect corrections, crash corrections, and save data safety checks.
- Balance and tuning, such as difficulty, reward rates, and control response.
- Performance, load time, and memory work on all target devices.
- Polish, accessibility, localization, and tests with external players.

**Work that does not belong here**
- New features or new game systems.
- Large structure changes to code that works. These changes add regression risk without a benefit to the player.
- Changes to the design of the core loop.
- Store submission and launch tasks.

**Exit condition:** The game is content complete, has no known blocking defects, and is ready for a release candidate.
