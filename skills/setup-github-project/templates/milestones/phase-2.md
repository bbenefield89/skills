**What this phase represents:** A Vertical Slice is one small, complete part of the game at the quality of the final product. It shows how the released game will look, sound, and feel. It also replaces Prototype shortcuts with the foundation that the subsequent phases build on. The slice is narrow in content and deep in quality.

**Work that belongs here**
- Final-quality art, audio, and UI for one level, mode, or area and its content.
- The full player flow around that part, such as the title menu, gameplay, pause menu, and settings.
- The standards that all subsequent content follows, such as the UI style system, file organization, and asset authoring rules.
- Foundation work: code structure for the systems in the slice, shared test tooling, and the build and release pipeline.

**Work that does not belong here**
- More content of the same type, such as more levels or more characters.
- New game systems that the slice does not need, such as progression, economy, or cloud saves.
- Structure changes that are useful only when a subsequent phase extends a system.
- Localization, store pages, and tests on the full range of devices.

**Exit condition:** One part of the game is playable from the title menu to the end of its core loop at release quality. The team can make more content with the same methods.
