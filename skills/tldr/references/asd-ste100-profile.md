# ASD-STE100 Issue 9 response profile

Use this profile to make TLDR responses close to ASD-STE100 Simplified Technical English. Apply it to the summary and the **Next step** section.

This profile is an original operational summary. It does not reproduce the controlled dictionary. It supports STE-aligned writing, but it does not prove formal compliance. The authoritative source is [ASD-STE100 Issue 9](https://www.asd-ste100.org/assets/files/ASD-STE100_ISSUE9.pdf).

## Application order

1. Preserve the exact meaning, safety information, code, commands, identifiers, quotations, and required domain terms.
2. Identify the text as an instruction, a description, a safety instruction, or a list.
3. Apply the vocabulary, sentence, and structure rules below.
4. Do the final review before you send the response.

## Vocabulary control

- Prefer common words that you know have a clear technical meaning.
- Use a word only with the intended part of speech and meaning.
- Use only the necessary form of a verb or adjective.
- Use project terminology from `CONTEXT.md`, official names, and exact user terms as technical nouns.
- Use a subject-specific technical verb only when it names the action more accurately than a common verb.
- Do not use a technical noun as a verb. Do not use a technical verb as a noun.
- Use one term for one item, concept, or action. Do not replace it with a synonym for variety.
- Exclude slang, idioms, regional words, and unclear jargon.
- Use American English spelling unless a project rule or exact quotation requires different spelling.
- If a word can be unclear, rewrite the sentence. Do not make a word-for-word replacement that changes the meaning.

The full Issue 9 dictionary controls approved words, parts of speech, meanings, and forms. This profile cannot reproduce that dictionary. If exact STE compliance is a requirement, check each uncertain word in the official dictionary and the applicable company glossary.

### Technical noun test

Use an uncontrolled noun only when it belongs to one of these subject categories:

1. Official parts and design items
2. Vehicles, machines, and their locations
3. Tools, support equipment, and their parts or locations
4. Materials, consumables, contaminants, and waste
5. Facilities, infrastructure, and logistics
6. Systems, components, circuits, functions, configurations, and parts
7. Mathematics, science, engineering, and formulas
8. Navigation and geography
9. Numbers, measurements, time, and their symbols
10. Exact text from labels, displays, signs, or other sources
11. Roles, persons, groups, organizations, and geopolitical entities
12. Parts of the body
13. Personal items, food, and beverages
14. Medicine and health
15. Official documents, document parts, standards, and guidance
16. Environmental and operating conditions
17. Colors
18. Damage and defects
19. Computer science and information or communication technology
20. Civil and military operations
21. Law and regulations
22. Animals, plants, and other life forms.

If no category applies, rewrite the text with controlled words. Use the project glossary when it contains the term. If it does not, use only an established term from the supplied domain material or current context. Do not change the glossary. Use the term only as a noun.

### Technical verb test

Use an uncontrolled verb only when it names a precise process in one of these subject categories:

1. Manufacturing, including material removal, addition, attachment, treatment, finishing, or shaping
2. Computer input, output, user-interface, application, or system operation
3. An established subject process in engineering, science, medicine, civil or military work, navigation, transport, or energy
4. Law or regulation.

Use a controlled verb when it gives the same meaning. Use the project glossary when it contains the term. If it does not, use only an established term from the supplied domain material or current context. Do not change the glossary. Use the term only as a verb.

## Dictionary method

- Read each entry as four fields: the word and part of speech, the approved meaning or alternatives, an STE example, and a non-STE example.
- Treat an uppercase entry word as approved. Treat a lowercase entry word as unapproved.
- For an approved entry, check its part of speech, approved meaning, permitted forms, and usage note.
- For an unapproved entry, select an approved alternative only when it keeps the same meaning.
- If a direct replacement changes the grammar or meaning, rewrite the full sentence.
- Read all help information. It can give usage guidance, restrict a meaning, restrict a word to one context, or give another important condition.
- Treat technical nouns and technical verbs as controlled project terminology. Do not assume that the general dictionary approves them.
- Use the project glossary with the dictionary. The glossary controls domain terms. The dictionary controls the surrounding language.

## Noun groups

- Keep an ordinary multi-word noun to three words or fewer.
- Preserve an official technical noun even when it is longer. Write it in full on first use. Then define one clear short form or use its official abbreviation.
- Use prepositions to divide a long noun group when no official term controls it.
- Use hyphens only when the connected words operate as one unit. Do not use hyphens only to reduce the word count.
- Use `a`, `an`, `the`, `this`, or `these` when grammar or context requires it.

## Verbs

- Use only a permitted dictionary form. Use the infinitive, command form, simple present, simple past, simple future, or permitted past participle.
- Avoid perfect and progressive verb constructions.
- Use a permitted past participle as an adjective that states a condition. Do not use it to make an unsupported verb construction.
- Use an `-ing` form only when it is an established technical noun or part of a technical noun.
- Use active voice. Name the person or thing that does the action.
- In a description, use passive voice only when the agent is unknown and an active sentence would change the meaning.
- Use a direct verb to state an action. Do not hide the action in a noun phrase.
- Do not use a phrasal verb when its combined meaning differs from the meanings of its parts.

## Sentences and lists

- Write one main idea in each sentence.
- Include the necessary subject, verb, object, article, and condition.
- Do not use contractions.
- Use a vertical list when one sentence contains many items, conditions, or actions.
- Introduce a vertical list with a colon. Start each item with an uppercase letter.
- Use a period for each complete list sentence and for the final item. Do not end an item with a comma or semicolon.
- Do not mix instructions and descriptive statements in the same list.
- Use stable connecting words and repeated key terms to show how related ideas connect.

## Instructions and workflow steps

- Limit each instruction sentence to 20 words.
- Put one instruction in each sentence. Combine actions only when they occur at the same time.
- Start an instruction with a command verb.
- If the user must know a condition first, put the condition first and add a comma before the command.
- Use a note only for supporting information. Do not put an instruction, limit, result, or safety requirement in a note.

## Explanations and descriptions

- Limit each descriptive sentence to 25 words.
- Give information gradually. Start with the core topic, and then add only the information needed for that topic.
- Use one topic in each paragraph. Start a new paragraph for a new topic.
- Limit each paragraph to six sentences.
- Repeat the same key terms when they identify the same concepts. Use clear connectors for cause, contrast, sequence, and result.

## Material warnings

- Put the safety instruction before the explanation.
- Use **WARNING** for a risk of injury or death.
- Use **CAUTION** for a risk of damage to data, software, equipment, or other property.
- If both risk levels apply, use **WARNING**.
- Start with the action or condition that prevents the harm. Then state the harm or possible result.
- Do not hide safety content in a note.

## Punctuation and word count

- Use standard English punctuation. Do not use semicolons.
- Use parentheses only for references, identifiers, abbreviations, forms, short explanations, or alternatives.
- Treat a colon before a vertical list as the end of the introduction for sentence-length checks.
- Count parenthetical text as one word in the host sentence. Also check the text inside the parentheses as a separate sentence.
- Treat a number, measurement, abbreviation, identifier, exact quotation, title, label, formula, or proper name as one fixed element for sentence-length checks.
- Treat a correctly hyphenated term as one word.

## Additional clarity checks

- Use `that` when it clearly separates a main clause from a dependent clause.
- Check each use of `with`. Rewrite the sentence if `with` can show more than one relationship.
- Make each pronoun refer to one clear noun. Repeat the noun if the pronoun can be ambiguous.
- Check words that look similar in another language. Make sure that each word has its correct English meaning.
- Use English words instead of Latin abbreviations such as `e.g.`, `i.e.`, and `etc.`.
- Use inclusive, gender-neutral language unless the subject requires a gender-specific term.
- Use a possessive form only when its owner is clear.

## Final STE review

Before you send the response, confirm these points:

- The response preserves the exact meaning and all material warnings.
- Each sentence has one main idea and stays within its applicable length.
- Instructions use commands. Conditions come before dependent actions.
- Descriptions use active voice unless the agent is unknown.
- Each term has one meaning, one form, and one consistent use.
- Noun groups are short unless they are official technical nouns.
- Pronouns, prepositions, and connectors do not cause ambiguity.
- The response has no contraction, idiom, slang term, hidden action, phrasal verb, or semicolon.
- The TLDR summary still follows its 100-word or five-bullet limit.
- The separate **Next step** moves the user toward the likely goal.
