# Scoped Grill Skills Design

## Goal

Create two scoped variants of the existing grilling wrapper skills:

- `scoped-grill-me`, based on `grill-me`
- `scoped-grill-with-docs`, based on `grill-with-docs`

The variants preserve the existing skills' ownership of interview behavior and question content. They add question numbering, a temporary scope ledger, scope enforcement, and repeated scope context in chat.

## Skill behavior

Each scoped skill delegates exactly as its source skill does:

- `scoped-grill-me` runs the grilling skill.
- `scoped-grill-with-docs` runs the grilling skill with the domain-modeling skill.

The scoped wrapper does not prescribe which questions to ask, reword generated questions, or alter the underlying grilling workflow.

## Temporary scope ledger

At the beginning of a scoped grilling session, create a uniquely named Markdown file in the operating system's temporary directory. The file contains exactly two semantic blocks:

```markdown
## TL;DR

<A concise description of what is being grilled.>

## IN SCOPE

- <Current scope item>
```

Update the ledger when the user's answers explicitly refine or change the session's goal or scope. Before asking every question, reread the ledger and compare the proposed question with `IN SCOPE`.

If the ledger cannot be created, read, or updated, do not ask another question. Report the failure because the skill cannot enforce its defining scope guarantee.

## Question contract

Start numbering at 1 and increment the number once for each question shown to the user. Do not use unnumbered labels such as "next question."

Every question response uses this shape:

```markdown
## TL;DR

<Current ledger TL;DR>

## IN SCOPE

<Current ledger IN SCOPE>

## Question N

<Question generated by the underlying skill>
```

The wrapper controls only the two context blocks, the heading, and the scope gate. The underlying skill controls the question content.

Do not ask a question outside `IN SCOPE`. When an exceptional off-scope question is genuinely necessary to continue the stated goal, identify it explicitly with a `SCOPE EXCEPTION` block and give the concrete reason before the numbered question.

## Repository integration

Add each skill as its own directory under `skills/` with a `SKILL.md`. Register both paths under the existing `general-skills` entry in `.claude-plugin/marketplace.json`.

Do not modify or deprecate the source `grill-me` or `grill-with-docs` skills.

## Validation

Verify that:

1. Both new skill manifests have their requested names and preserve the source delegation behavior.
2. Both define the same temporary ledger, numbering, chat-output, failure, and scope-exception contracts.
3. Both are registered exactly once under `general-skills`.
4. The marketplace manifest remains valid JSON and every registered new skill path exists.
